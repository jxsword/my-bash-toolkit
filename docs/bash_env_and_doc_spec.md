# bash 环境与文档自动化实施规格

本文档是 `.bash-version` 版本锁定、环境检测函数、脚本头部 tag 与文档抽取的唯一实施规格。编码规范见 shell_rules.md，决策依据见 docs/decision_log.md（DR-005/006/007）。

## 1. 环境标识符

`# env:` 标注与测试跳过共用的 canonical 标识符（只允许以下三个 + `unknown` 内部值）：

| 标识符 | 含义 | 识别规则 |
|---|---|---|
| `ubuntu-26.04` | 原生 Ubuntu 26.04（含 GitHub Actions ubuntu-26.04 runner） | 非 WSL/MSYS，/etc/os-release ID=ubuntu 且 VERSION_ID=26.04 |
| `wsl-ubuntu-26.04` | WSL2 中的 Ubuntu 26.04 | /proc/version 含 microsoft（忽略大小写）且 os-release 为 ubuntu 26.04 |
| `git-bash` | Windows Git for Windows（MSYS2）bash | MSYSTEM 非空且 OSTYPE 以 msys 开头 |

识别顺序：先判 `git-bash`，再判 WSL，最后原生 linux；均不匹配返回 `unknown`。
bash 版本来源：`BASH_VERSINFO[0..2]`（major.minor.patch）。

## 2. lib/env.sh 接口

| 函数 | 签名 | 行为 |
|---|---|---|
| `env_detect_platform` | 无参数 | stdout 输出 `msys` / `wsl` / `linux` |
| `env_detect_id` | 无参数 | stdout 输出 §1 标识符或 `unknown` |
| `env_is_supported` | `env_is_supported <id>...` | 当前 env id 在参数列表中 → 0，否则 1（供测试 skip） |
| `bash_env_check` | `bash_env_check [--quiet]` | 读 .bash-version 判定版本区间，见下 |

`bash_env_check` 细则：
- 配置文件定位：默认 `<仓库根>/.bash-version`（由 BASH_SOURCE 向上推导，兼容 git bash）；可用环境变量 `BASH_VERSION_FILE` 覆盖。
- 文件格式：单行 `MIN-MAX`（语义化 X.Y.Z，端点含）；`#` 开头为注释行；文件缺失或格式非法 → 退出码 2。
- 比对算法：三个 X.Y.Z 字符串经 `sort -V` 排序判定（三环境 coreutils 均含，无外部依赖）。
- 判定：当前 < MIN 或 > MAX → 退出码 1；区间内 → 退出码 0。
- `--quiet`：不输出报告，仅退出码。
- 退出码语义：`0`=支持；`1`=版本不支持（打印当前版本、允许区间与更新指引）；`2`=配置缺失/非法。
- 报告输出样例（stdout）：

```text
[env] platform=wsl id=wsl-ubuntu-26.04 distro=Ubuntu 26.04.1 LTS
[env] bash=5.3.9 range=5.2.0-5.3.9 verdict=OK
```

- 双模式：被执行（非 source）时进入 `main` 直接运行 bash_env_check；被 source 时只定义函数。

## 3. .bash-version 文件规范

```text
# bash 支持区间（语义化版本，端点含）；更新流程见本文档 §8
5.2.0-5.3.9
```

初值 MIN=5.2.0（三目标环境全覆盖），MAX=5.3.9（2026-10-30 WSL Ubuntu 26.04.1 实测 `bash 5.3.9(1)-release`）。CI 侧 ubuntu-26.04 镜像与 git bash 的实测值在对应阶段回填核对。

## 4. 脚本头部元数据 tag

位置：shebang 之后、第一条非注释代码或空行之前的连续注释块。语法 `# key: value`（key 全小写连字符）。

| tag | 必需 | 说明 |
|---|---|---|
| script-name | 是 | 与文件名一致（不含 .sh） |
| description | 是 | 一句话功能说明 |
| usage | 是 | 用法行；库文件写「（库，被 source）」 |
| env | 是 | §1 标识符列表，逗号分隔；只写实际支持并测试过的环境 |
| category | 是 | 10 域之一（或 `域/子域`） |
| option | 否（可重复） | `option: -n, --dry-run    仅打印将执行的动作` |
| example | 否（可重复） | 一条可复制的调用示例 |
| deps | 否 | 外部依赖，逗号分隔 |

示例：

```bash
#!/usr/bin/env bash
# script-name: sudo-nopasswd
# description: 开启/恢复指定用户的 sudo 免密（写入 /etc/sudoers.d）
# usage: sudo-nopasswd <on|off|status> [用户名] [--dry-run]
# option: -n, --dry-run    仅打印将执行的动作，不修改系统
# example: sudo-nopasswd status
# env: ubuntu-26.04, wsl-ubuntu-26.04
# deps: sudo, coreutils
# category: security
```

## 5. 函数级环境标注

- 每个函数定义前**必须**有紧邻注释行 `# env: <id,...>`（可选一行 `# fn: <一句话说明>`）；私有函数（`_` 前缀）同样必需。
- 缺失由 hooks/check-metadata.sh 报错阻断（检测函数定义行前 3 行内无 `# env:`）。
- 不支持的环境不写入 `# env:`——测试与文档自动跳过该环境（"不支持的直接不用测试"）。

## 6. gen-docs.sh 抽取规则

- 扫描 `scripts/**/*.sh`（含 lib/），按头部 `category` 分组（缺失归 `uncategorized`）。
- 每个脚本输出：名称、description、usage、option 列表、example 列表、env 徽标、deps、函数表（函数名 | env | fn 说明）。
- 输出 `docs/SCRIPTS.md`；文件首行 HTML 注释声明「AUTO-GENERATED by scripts/dev/gen-docs.sh」+ 生成时间；生成物入库、禁止手改。
- Makefile `docs` 目标触发；脚本注释变更后随代码同一提交重新生成。

## 7. hook 校验规则

- `hooks/check-metadata.sh`（pre-commit local hook，`types: [shell]`）：
  - 每个暂存 .sh：§4 必需 tag 缺失 → 报错并列出缺失项；
  - 每个函数定义（`name()` 或 `function name`）前 3 行内无 `# env:` → 报错（file:line）；
  - lib/*.sh 同样校验（usage 写「（库，被 source）」）。
- `hooks/line-length.sh`：.sh 中长度 >80 的行 → 报错（file:line）；行尾 `# noqa:line-length` 豁免。
- `rules_check_test/bad/` 目录为故意违规的固定用例，pre-commit 各 hook 以 `exclude: ^rules_check_test/bad/` 跳过，由 run_checks.sh 专门校验。

## 8. .bash-version 更新 checklist

新 bash 版本出现（新环境或系统升级）时：

1. `bash --version` 实测记录；`make env-check` 确认当前判定与指引。
2. `make test` 本地全绿（Stage 1）→ 人工确认。
3. CI 全绿（Stage 2）；`make check-rules` 通过（golden 复核，见下）。
4. 更新 `.bash-version` 的 MIN 或 MAX 并提交；提交信息注明实测环境与版本。
5. 工具（shfmt/shellcheck）升级时同步复核 rules_check_test/expected/ 的 golden 输出。

## 9. 三阶段测试流水线

1. **Stage 1 本地 WSL ubuntu2604**：`make env-check && make test` 全绿 → 用户手动确认（闸门 B）。
2. **Stage 2 GitHub Actions**：`runs-on: ubuntu-26.04`，`pre-commit run --all-files` + `make check-rules` + `make test`。
3. **Stage 3 git bash**：用户手动克隆到 Windows 工作区 → `./run_tests.sh`（内置 bash_env_check 预检，git bash 无 make 可跑）→ 问题按脚本模块修复，修复后从 Stage 1 依序重跑。

顺序强制，不得跳步；不支持的环境（函数/脚本 `# env:` 未标注）在 bats 中直接 skip。
